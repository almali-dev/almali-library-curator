# Almali Library Curator for Plex — v1 (feature)

Feature doc for the ODD implementation of **Almali Library Curator for Plex**, version 1.
Source of truth for scope: `docs/Almali-Library-Curator-for-Plex.md` (the requirements file, Nov 2, 2026 · @Miquel Àngel).
This document quotes the requirements verbatim where a rule, message or example must not drift.

Status: T1–T5 done (v0.1.0–v0.5.0) · T6 implemented and parent-verified, independent verification missing · T7–T15 not started.

## Specs

### S1 — Product intent and v1 boundaries

> Almali Library Curator for Plex shows what nobody watches in a Plex library, says why in one sentence per item, and removes only what the owner marks, after a grace period and a final re-check.

> **The core idea.** No rule builder. A fixed set of categories, each with a few thresholds, and every result shown in place with its reason, size, disk and rating.

Goals (v1), verbatim:

1. Detect the categories in the Detection section, per series, per season and per movie.
2. Show each candidate with its reason, size, disk and rating, in the same place where it is acted on.
3. Respect three kinds of protection: protected library, high rating, kept by hand.
4. Run the whole removal lifecycle: grace period, Leaving soon collection, final re-check, deletion, no re-download.
5. Ship as a Docker image with an installer and an Unraid Community Applications template.

Non-goals (v1), verbatim:

- Automatic marking per category. The owner will design it later; v1 must not block it.
- A free-form rule builder.
- Freeing a target amount of space ("free 2 TB"). The owner's goal is knowing what is not watched, not a quota.
- Managing downloads, requests (Overseerr/Jellyseerr) or anything outside Plex, Sonarr and Radarr.
- Jellyfin or Emby support.

Anti-goals (a failure even if it works), verbatim:

- Deleting anything the owner did not mark.
- Deleting something a user started watching during the grace period.
- Sonarr or Radarr downloading a removed item again.
- Reporting freed space that was not actually freed (for example a hardlinked file whose other link remains).
- A result the owner has to look up somewhere else to understand.

### S2 — Data sources and degraded operation

> Plex is the only required source; every other connection adds precision or an action and the app must work, with reduced features, without it.

| Source | Required | Used for | Without it |
| --- | --- | --- | --- |
| Plex Media Server | Yes | Libraries, items, seasons, file paths, sizes, per-user play history, collections, Home hubs | App cannot run |
| Tautulli | No | Longer and more reliable per-user history | Plex history only |
| Sonarr | No (optional) | Series status (continuing, ended, cancelled), deletion, unmonitor, import exclusion | Series are removed through Plex instead (S15) |
| Radarr | No (optional) | Deletion, import exclusion | Movies are removed through Plex instead (S15) |
| TMDB (API key) | No | Ratings and production status when Sonarr has none | Plex's own rating only |
| Unraid host filesystem | No | Which array disk or pool holds each file, hardlink count | Size shown without disk; freed space marked as estimated |

> - **Users.** "A user" is a Plex account with access to the server, including managed Home users. The owner can exclude accounts (for example a guest) from all calculations.
> - **IMDb.** IMDb has no free public API. v1 uses the rating Plex already stores (often IMDb or Rotten Tomatoes, depending on the agent) and TMDB as a fallback. Which rating to show is a setting.
> - **Credentials.** Tokens and API keys are entered in the app, stored encrypted at rest, never logged and never returned in full by any API.

### S3 — Detection categories

Five fixed categories; each candidate carries the category, the unit it applies to (series, seasons or movie) and a one-sentence reason built from the facts that made it match.

| Category | Applies to | Matches when | Default threshold | Example reason |
| --- | --- | --- | --- | --- |
| Stalled series | The unopened seasons | Someone watched part of the show, then later seasons sat with no play | No play of those seasons for 6 months | Anna watched S1 in March 2025. S2 and S3 were never opened. |
| Never watched | Series or movie | No user has played any part since it was added | Added more than 3 months ago | Added April 2024. 0 episodes played by any of the 3 users. |
| Cancelled, no viewers | Whole series | Sonarr or TMDB says ended or cancelled, and no user is mid-show | Last play more than 6 months ago | Cancelled in 2022. Last play August 2023, nobody mid-season. |
| Seasons everyone finished | Finished seasons only | Every user who follows the show has watched those seasons, and later seasons are still pending | All followers finished them more than 1 month ago | Marc and Anna (the only followers) both finished S1. S2 is in progress. |
| Movies not rewatched | Movie | Watched at least once, nobody played it since | Last play more than 18 months ago | Watched once by Marc in February 2024. Nobody since. |

Definitions, verbatim:

- **Follower of a show:** a user who has played at least one episode of it. Users who never started it do not count towards "everyone".
- **Watched:** an episode or movie marked watched in Plex, or played past 90% in history.
- **Mid-show:** a follower who has watched some but not all aired episodes and played one within the stalled-series window.
- An item can match several categories; it appears once under All, with every matching reason.
- Thresholds are global settings in v1. Per-library thresholds are a later decision.
- A scan runs on a schedule (default daily) and on demand. Results show when the last scan ran.

### S4 — Protection

> A protected item is never a candidate and never deleted; it is listed in the Protected view with what protects it and the category it would otherwise match.

| Protection | Set by | Covers | Example |
| --- | --- | --- | --- |
| Protected library | Settings, per Plex library | Everything in that library | Filmoteca: Blade Runner, 2001: A Space Odyssey, The Sting |
| High rating | Settings, one minimum rating (default 8.0) | Any item at or above it, seasons included | Severance, 8.7 |
| Kept forever | "Keep forever" button on any row | That item only | The Office (US) |

> - Protection is checked at scan time and again at the final re-check before deletion.
> - Removing a protection (unprotecting a library, lowering the threshold, undoing "Keep forever") only makes items candidates again; it never marks them.
> - The rating rule can be switched off.

### S5 — Removal lifecycle

> Nothing is deleted unless the owner marked it, the grace period has passed, and a final re-check confirms it still qualifies and nobody has started it.

> The final check is the only path to deletion; a failed check, an undo or "Keep it" sends the item back to the candidates.

1. **Candidate.** Found by a scan. No change in Plex, Sonarr or Radarr.
2. **Marked.** The owner presses "Mark for removal". The grace period starts (default 14 days, range 3 to 60). Undo is possible until deletion.
3. **Leaving soon.** The item is added to a Plex collection named "Leaving soon" (name configurable), promoted to every user's Home. The collection is created if missing and only ever holds marked items.
4. **Final re-check** on the last day. The item is kept, and leaves the collection, if any of these is true:
   - it no longer matches its category;
   - it became protected;
   - any user played any part of it after it was marked. The reason is shown in Leaving soon ("Removal cancelled: Marc started watching on 30 October").
5. **Deleted.** Through Sonarr (series or the exact seasons) or Radarr (movie) when that service is configured and enabled for deletions; otherwise through Plex, which removes the media item and its files (S15). When an arr service removes it, the item is unmonitored and added to the import exclusion list in the same step so it is not downloaded again. The item leaves the collection.
6. **Recorded.** History keeps title, unit, size, disk, date, reason and who marked it. Freed space is the sum of files whose last link was removed; hardlinked files are counted only when every link is gone.

### S6 — Failure rules, dry run and kill switch

> - If Sonarr or Radarr is unreachable or returns an error, nothing is deleted, the item stays in Leaving soon flagged "Removal failed" with the error, and it retries at the next scan. The same holds when Plex refuses the deletion, for example because the server does not allow deleting media (S15).
> - "Deleted" is shown only after the app confirms the files are gone from disk. A 2xx from Sonarr or Radarr alone is not proof.
> - A dry-run mode does every step except steps 3 and 5 and reports what would happen.

> - **Safety.** Deletion only through the lifecycle above. A global kill switch in Settings stops all deletions at once. Every deletion is logged before and after it runs.
> - **Verified outcomes.** A success message, a "Deleted" status or a freed-space figure comes only from a checked result, and each has a test for its failure branch.

### S11 — Library reuse (the stack Plex Smart Cache already proves)

The owner asks for the libraries Plex Smart Cache already uses, so both apps run on a proven set instead of a new one. Reuse means the same library, the same major version and the same purpose — never shared code, a shared database or a runtime dependency between the two apps.

| Library | PSC role | Role here |
| --- | --- | --- |
| Flask 3.1 | web framework | web framework |
| Flask-WTF 1.2 | form and CSRF handling | CSRF protection on every mutating route (S9) |
| Gunicorn 25 | WSGI server | WSGI server |
| requests 2.33 | outbound HTTP | Plex, Sonarr, Radarr, Tautulli and TMDB clients |
| pydantic 2.12 | payload validation | validation of every external API payload |
| pydantic-settings 2.13 | settings validation | validation of the settings file and the `ALC_` environment overrides |
| psutil 7.2 | host inspection | which array disk or pool holds each file (S2) |
| cryptography 46–50 (not in PSC) | — | Fernet encryption of the Plex token at rest (S12); added on the owner's decision, L70 |
| Tabler 1.0.0-beta20 (vendored CSS) | dashboard design system | the same vendored stylesheet, copied into this app in T9, with its LICENSE, plus this app's own HUD layer on top of the tokens documented in PSC's `design/system.md` |

Deliberately not reused: `aiohttp` and `flask-socketio` (the app is synchronous server-rendered in v1), `flask-limiter` (the rate limit the requirements ask for is on outbound Plex reads, not on inbound routes), `pyyaml` (settings are JSON), `eventlet` (the default WSGI worker stays plain Gunicorn).

Every one of these libraries except `cryptography` is already installed in the system Python; the project `.venv` (`--system-site-packages`) adds `cryptography`, so the suite runs with `.venv/bin/python` (L71).

### S12 — Plex connection from the app (T9a)

> "Diu que plex no està configurat, però no es configura?" (owner, L68) — decisions in L70: "Afegir cryptography (Fernet) (recomanat)" and "Adreça + token manual (recomanat)".

1. **Form.** The wizard's Plex step and the Connections screen show a form with the Plex address and the Plex token (a password field, never pre-filled), submitted by `POST /connections/plex` behind CSRF. The page explains in one translated line where the owner finds the Plex token.
2. **Validation before anything is stored.** The address must be an `http` or `https` URL with a host and no user info, query or fragment. An invalid address, or a token that is empty when none is stored yet, shows a translated error and changes nothing: the settings file, the secrets files and the database stay byte-for-byte as they were.
3. **Test before save.** The app tests the submitted address and token against Plex with the existing client. If Plex is unreachable, refuses the token or answers anything but a valid server identity, the owner sees a translated error naming which of the three happened and nothing is stored.
4. **Storage.** On success the address goes to the settings file as `plex_base_url`. The token is encrypted with Fernet (`cryptography`) and written to `<config_dir>/secrets.json`; the key lives in `<config_dir>/secrets.key`. Both files are owner-only (mode 0600), are created atomically so concurrent Gunicorn workers cannot race, and are never served. The token never appears in the settings file, a log line, a page, a flash message or an error.
5. **Never returned in full.** After saving, the screens show only that a token is stored and its last four characters (for example `••••ab12`).
6. **Keeping the token.** Submitting the form with an empty token field while a token is already stored keeps the stored token and tests the new address with it.
7. **Forget.** A "Forget the Plex token" action (`POST /connections/plex/forget`, CSRF) deletes the stored token; Plex then reports "not configured".
8. **Environment wins.** `ALC_PLEX_BASE_URL` and `ALC_PLEX_TOKEN` keep overriding the stored values. While either is set, the form is replaced by a translated note that the environment manages Plex, and `POST /connections/plex` refuses with that message and stores nothing.
9. **Unreadable secrets fail safe.** A missing, corrupted or undecryptable secrets file, or a missing or wrong key, never stops the app from starting: Plex reports "not configured" with a translated warning to enter the token again, and a structured log event records the failure without any secret.
10. **Copy and docs.** Every new string exists in en, ca and es; the README's configuration section documents the in-app Plex connection, the two secrets files and the environment override.

### S13 — Plex sign-in (T9c)

> Owner decision (L75, verbatim choice "Sí, login amb PIN com a principal"): the PIN flow at plex.tv is the primary way to connect; manual address and token entry stays as the alternative. The deletion engine stays Sonarr/Radarr (same choice), so the Plex API never deletes media.

1. **The flow.** The wizard's Plex step and Connections show a "Sign in with Plex" action. The app creates a PIN with `POST https://plex.tv/api/v2/pins` (headers `X-Plex-Client-Identifier` and `X-Plex-Product`), shows the code and the link `https://app.plex.tv/auth#?clientID=<client id>&code=<code>`, and polls `GET https://plex.tv/api/v2/pins/<pin id>` every two seconds for at most fifteen minutes. When `authToken` arrives, the app tests it against the configured Plex server and stores it like any other token.
2. **Classic token, never the short-lived JWT.** The PIN is requested without `strong=true`. The token is long-lived, because the app scans on a schedule and a seven-day JWT would expire under it. The stored token is the account token from plex.tv; it is encrypted with the same Fernet store as T9a and never returned in full.
3. **Discovering the address.** With the account token, the app may read `GET https://plex.tv/api/v2/resources` and offer the owner's own servers with their local addresses. The owner still chooses; the app never writes an address the owner did not pick.
4. **Outbound rule.** S9 says outbound calls go only to the configured services. This task amends it: the app may reach `plex.tv` and `clients.plex.tv` for the sign-in flow and the resource list, and nowhere else.
5. **Failure is explicit.** A refused PIN, an expired PIN, a user who cancels, or a plex.tv that cannot be reached shows a translated message and stores nothing. The manual form stays usable at all times, including while a sign-in is pending.
6. **No token in the URL.** The PIN code is not a credential and may be shown; the auth token never appears in a URL, a page, a log line or an error.
7. **Copy and docs.** Every new string exists in en, ca and es; the README documents the sign-in flow and the one outbound exception.

### S14 — Curated Plex libraries (T9b)

> The wizard and Settings must let the owner choose which Plex libraries the app curates (S7's "library selection"). Parent decisions, L77: an empty selection means **every** library is curated (no restriction), the history ledger stays global, and the sync reports both counts.

1. **The scope setting.** `Settings.curated_libraries` is a tuple of Plex library keys, stored in `settings.json` and overridable with `ALC_CURATED_LIBRARIES` (comma separated). **An empty selection means every library is curated**: a fresh install and every install upgraded from v0.10.0 keep curating everything, so no existing behaviour breaks and no legacy sentinel is needed. A non-empty selection restricts the app to exactly those library keys. An empty environment value is treated as unset, the same rule the Plex variables already follow, so a stored selection keeps applying; there is no restriction only when neither the file nor the environment selects anything.
2. **The sync keeps the library list.** The sync still stores a `libraries` row for every Plex section, because that list is what the owner picks from. It only fetches items, seasons and episodes for the curated libraries, so an uncurated library produces no outbound request at all. The summary reports both `libraries` (sections seen) and `curated_libraries` (sections actually synced).
3. **One shared scope helper.** A new `almali_library_curator/library_scope.py` owns the rule: the curated keys, the curated library ids, the curated item ids and whether a library or item is curated. The sync, the detection engine, the lifecycle engine, the per-item enrichment steps and the web views all ask it, so the rule exists once. The protection engine follows the scope implicitly, because the detection engine never offers an uncurated item to it.
4. **The screens follow the scope.** Candidates, Protected, Leaving soon, the summary cards and the disk count of the "// SOURCES" panel count only curated libraries; the Plex user count and the Tautulli history line stay server-level facts, because users belong to the server and not to a library. Items of a library that was curated and later deselected stay in the database (deleting them would cascade into the removal requests, the candidates and the history) but are never shown, detected or acted on.
5. **The history ledger stays global.** History and freed space record what the app already did; deselecting a library never erases that record, and the history screen keeps showing it.
6. **Nothing may be deleted outside the scope.** A removal request whose library is no longer curated is cancelled with a new reason `not_curated` during the re-check, never deleted. Marking an item of an uncurated library is refused with a translated error and changes nothing.
7. **The wizard and Settings.** Each library has a "curated" checkbox, checked by default, and a "protected" checkbox that is disabled while the library is not curated. A protected library that is not curated is refused with a translated error and nothing is saved.
8. **Tests.** Every rule is tested through the public interface: the settings round-trip and the environment override, the sync storing every library row but only the curated items (and making no request for the others), the screens counting only curated libraries, the history staying global, the `not_curated` cancellation, the refusal to mark an uncurated item and the refusal to protect an uncurated library. The per-item enrichment steps follow the scope too: a deselected library's items are not linked to Sonarr or Radarr, their file facts are not read and TMDB is not asked about them.

### S15 — Optional Sonarr and Radarr, Plex as the deletion fallback (T9d)

> Owner requirement change (L78, verbatim): "El que vull és que facin servir el major nombre de persones possibles facin servir l'eina. Per tant es podria fer que sonarr i radarr siguin activables o no, però plex obligatori. Si es posa només plex, llavors és plex qui s'encarrega. Si s'afegeix , sonarr o radarr o els 2, llavors es fa per allà." Plex is the only required connection; Sonarr and Radarr are optional and can be switched off, and whichever service is responsible for a unit type removes it.

1. **Routing.** Every removal is routed by unit type. Movies go through Radarr when Radarr is configured and enabled for deletions, and through Plex otherwise. Series and seasons go through Sonarr when Sonarr is configured and enabled for deletions, and through Plex otherwise. A configured service always wins for its own unit type: the app never silently removes through Plex something that a configured Radarr or Sonarr owns. When that service cannot handle the item (for example the item could not be linked to it and has no identity), the removal fails and retries; the app never falls back to Plex behind the owner's back, because that service may download the item again. That case gets its own translated message naming the service and the missing identity, not the generic service failure the owner cannot act on.
2. **Two switches.** Settings carry `radarr_deletes` and `sonarr_deletes`, both true by default. Switching one off means that service is not used for deletions even when it is configured; its other jobs (status, linking) keep working.
3. **The arr path does not change.** When the responsible service is configured and enabled, the deletion runs exactly as T7 built it: unmonitor, import exclusion, delete with files, the claim, the final check and the verified outcome.
4. **The Plex path.** Plex removes the media item through its own API (`DELETE /library/metadata/{ratingKey}`), which deletes the item's file. A movie is one request for the movie. A season is one request per episode of that season, so the other seasons and the series stay untouched. A series is one request per episode. The app never deletes the series container itself. The rating keys come from the episodes table, and a season scope reaches its episodes through the series row the request points at.
5. **No import exclusion, and always a warning.** The Plex path cannot unmonitor and cannot add an import exclusion. When the responsible arr is configured but switched off, the screens say so plainly wherever the item appears, because that arr may download the item again. The warning is never suppressed.
6. **The verified outcome stays.** The Plex path stats every file of the scope before and after, exactly like T7: "deleted" appears only when every file is gone, the freed space is inode-aware, a present or unknown file leaves the request in "Removal failed" with the error, and the next scan retries.
7. **A refused deletion.** When Plex refuses (for example because the server's "Allow media deletion" setting is off), nothing is deleted, the request stays in Leaving soon flagged failed, and the message names the setting. The refusal is its own error, distinct from a network failure and from a rejected token, so the app can say which one happened. The app never reports a deletion it did not confirm on disk.
8. **Plex is required.** The wizard's first step is Plex and cannot be completed without it; the Connections screen marks Plex as required, and the health report says the app is not ready without it. The rest of the connections stay optional.
9. **Tests.** Every rule is tested through the public interface with the fake Plex, Sonarr and Radarr servers: the routing per unit type and per switch, the arr path unchanged, the Plex requests for a movie, for one season and for a series, the season scope leaving the other seasons alone, the verified outcome and its failure branches, the refused deletion, and the warning when a configured arr is switched off. A dry run sends no delete request at all, and the removal never touches an item outside the curated scope of S14.

### S16 — Robustness of the removal scope and the stored failure text (T9e)

> Parent-owned, from the native review advisories of T6, T7 and T9 (L81). Three defects that the review rounds recorded as later work, grouped because they share the same seams: the scope carrier and the failure text.

1. **One damaged scope never breaks a screen.** A removal request whose scope carrier cannot be read is reported as unreadable and skipped; it never raises out of `open_requests`, the candidates view, the Leaving soon view or the history view. The request keeps its state and is retried, and the owner sees it as unreadable instead of the whole page failing.
2. **A seasons scope never falls back to the series.** A request whose unit is seasons but whose season rows are missing is never treated as the series scope. It fails with its own translated reason, so no backend can delete more than the owner marked. The season rows are the only source of truth for a seasons scope.
3. **The failure text is stored as a key, not as text.** The stored failure keeps the translation key, and the screen translates it in the reader's language. A failure recorded in Catalan is read in Spanish or English, and a locale change never rewrites history. The stored value keeps the same shape as today's (`removal.failed.*`), so the existing rows stay readable.

### S17 — Login, session cookie, brute-force guard and log redaction (T11)

> Owner decisions (L114, verbatim choices): "Variables d'entorn (recomanat)", "Desactivada per defecte (recomanat)", "Tasca pròpia després de la T11 (recomanat)", "Retard o bloqueig intern (recomanat)". S9, verbatim: "Login required (user and password set at install), CSRF protection, secure session cookie, secrets encrypted at rest and never logged, outbound calls only to the configured services (plus `plex.tv` and `clients.plex.tv` for the Plex sign-in of S13)."

1. **Credentials from the environment.** `ALC_AUTH_USER` and `ALC_AUTH_PASSWORD` set the one login. They are secret settings: never written to `settings.json`, never shown, never logged. At start the password is hashed in memory with Werkzeug's `generate_password_hash` (already installed with Flask, no new dependency); the plain text is not kept in the settings object and is never stored on disk.
2. **Fail closed.** Without both variables every screen and every action answers a translated "login is not configured" page with status 503 that names the two variables; nothing is ever served open. `/healthz` keeps its liveness contract (200, `status: ok` while the database is ready) and adds `"auth"` to `missing` (and `ready: false`) while the login is not configured.
3. **Public routes.** Only `/healthz`, `/static/*` and `/login` are reachable without a session. Every other GET screen redirects (303) to `/login?next=<path>`; `next` is honoured only when it is a relative path on this app (no scheme, no host, no `//`), otherwise the login lands on Library health. The JSON `POST /scan` answers 401 with a JSON body instead of a redirect.
4. **Login and logout.** `GET /login` shows a translated form (user, password); `POST /login` is CSRF-protected, compares the user with `hmac.compare_digest` and the password with `check_password_hash`, clears the old session before storing the new one (no fixation), and marks it permanent. A failure shows one translated message that never says which field was wrong. `POST /logout` (CSRF) clears the session and returns to `/login`. The layout shows a logout button.
5. **Session cookie.** Always `HttpOnly`, `SameSite=Lax`, lifetime 12 hours. `Secure` is off by default because the web UI is plain HTTP on the LAN; `ALC_SECURE_COOKIES=true` turns it on for HTTPS behind a proxy. The signing key file must hold at least 32 bytes and is kept owner-only (0600); a shorter key is replaced.
6. **Brute-force guard.** In-process, no new dependency: after 5 failed logins from the same client address within 15 minutes, that address is locked for 15 minutes; a locked attempt answers 429 with a translated message and the password is not checked. A successful login clears that address's failures. The count lives in the process (one Gunicorn worker, T12).
7. **Log redaction.** A root logging filter replaces the value of any structured field whose name contains `password`, `token`, `secret`, `api_key`, `apikey`, `authorization` or `cookie` with `***`. Login events (`auth_login_succeeded`, `auth_login_failed`, `auth_login_locked`, `auth_logout`) carry the client address and never the password; the user name is logged only on success.
8. **CSRF everywhere, proven.** One parametrised test sends every mutating route (all `POST`s in `web/` and `app.py`, `/login` and `/logout` included) without a token and expects 400 with nothing changed.
9. **Copy and docs.** Every new string in en, ca and es; the README documents `ALC_AUTH_USER`, `ALC_AUTH_PASSWORD` and `ALC_SECURE_COOKIES`, the 503 when the login is missing, and the development credentials of L38 (`admin`/`admin`) as an example to export, never as a default in code.
10. **Review corrections (L119).** (a) The lockout admits attempts atomically: a pending attempt counts as a failure from the moment it is admitted, so overlapping requests from one address never get more than 5 password checks in the window, and a success removes only its own pending failure and never lifts a lock another attempt set meanwhile. (b) Redaction reaches every handler on the root logger, including handlers that existed before `configure_logging`, and records from child loggers. (c) The success event never writes a user name that contains the password (it is written as `***`; decided at start from the plain text, L120). (d) `ALC_TRUSTED_PROXIES` (default `0`) is the number of reverse proxies in front of the app; when it is above 0 the client address comes from `X-Forwarded-For` through that many hops (Werkzeug `ProxyFix`), so the lockout is per real client behind a proxy; at 0 the header is ignored, so it cannot be spoofed on a plain LAN.
